# Penalty Live Feed — монитор пенальти в реальном времени

Скрипт опрашивает live-источники футбольных данных и сообщает о пенальти,
как только событие появляется в фиде: назначение (VAR), гол с пенальти,
незабитый пенальти, отмена, серия пенальти.

## Почему не Flashscore напрямую

У Flashscore нет официального API, а его внутренний push-фид закрыт и
нестабилен для сторонних интеграций. Данные у Flashscore и Sofascore —
из одних и тех же провайдеров, поэтому монитор использует:

| Источник | Ключ | Стоимость | Особенности |
|---|---|---|---|
| `sofascore` (default) | не нужен | бесплатно | неофициальный API; может отдавать 403 с датацентровых IP |
| `api-football` | `API_FOOTBALL_KEY` | free 100 req/день, платно от ~$29/мес | официальный, один запрос `/fixtures?live=all` покрывает все live-матчи |

Режим `--source auto` (по умолчанию): пробует Sofascore, при недоступности
переключается на api-football, если задан ключ.

## Задержка

Это polling, а не push. Событие детектится в течение `interval + задержка
источника` — на практике ~15–60 секунд от момента назначения пенальти.
Самый ранний сигнал — VAR-проверка (`penalty_var` / `penalty_awarded`).
Если нужна задержка в единицы секунд (беттинг-сценарии) — нужен платный
push-провайдер (Sportradar, LSports), это другой бюджет.

## Запуск

```bash
pip install requests

# проверка доступности источника — один проход
python3 penalty_monitor.py --once

# постоянный мониторинг (Sofascore, опрос каждые 20 сек)
python3 penalty_monitor.py --interval 20

# через api-football
API_FOOTBALL_KEY=xxx python3 penalty_monitor.py --source api-football --interval 15

# автономный запуск на сервере (паттерн проекта)
nohup python3 penalty_monitor.py --interval 20 > logs/penalty_feed.log 2>&1 &
```

## Куда приходят алерты

1. **stdout** — строка вида `⚽ ГОЛ С ПЕНАЛЬТИ 67' Спартак — Зенит (Спартак) — Иванов [РПЛ]`
2. **JSONL** — `penalties.jsonl` (путь: `--jsonl`), по одному JSON-объекту на событие
3. **Telegram** — если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`
4. **Webhook** — POST JSON на `PENALTY_WEBHOOK_URL`, если задан

## Типы событий (`kind`)

| kind | значение |
|---|---|
| `penalty_awarded` | назначен пенальти (VAR подтвердил) — только api-football |
| `penalty_var` | идёт VAR-проверка/решение по пенальти |
| `penalty_goal` | пенальти реализован |
| `penalty_missed` | пенальти не забит |
| `penalty_cancelled` | пенальти отменён после VAR |
| `penalty_shootout` | удар в послематчевой серии |

## Дедупликация и рестарты

Ключи отправленных событий хранятся в `penalty_state.json` (`--state-file`) —
после рестарта старые события не алертятся повторно. Первый проход после
чистого старта заполняет state без алертов (чтобы не заспамить событиями,
случившимися до запуска); флаг `--backfill` отключает это поведение.

## Flashscore: разведка фида

`flashscore_probe.py` — скрипт для запуска на машине с открытым интернетом.
Сам достаёт токен `x-fsign` из JS сайта, проверяет live-фид `d.flashscore.com`
и фиды деталей матча, сохраняет образцы ответов в `flashscore_samples/`.
По его выводу пишется полноценный источник `FlashscoreSource` для монитора.

```bash
python3 flashscore_probe.py
```

## Ограничения

- Sofascore — неофициальный источник: возможны блокировки по IP и смена
  формата без предупреждения. api-football — официальный запасной вариант.
- Скрипт не тестировался из среды разработки (исходящая сеть к спортивным
  API там закрыта политикой) — первый запуск делайте с `--once` и смотрите
  вывод.
